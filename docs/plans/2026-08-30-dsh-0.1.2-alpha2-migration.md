# @huanlin/dsh-plugin-better-glob · dsh 0.1.2-alpha.1 → alpha.2 迁移指南

> 分析基准：dsh tag `dsh-v0.1.2-alpha.1`（cd5ef81481）→ `dsh-v0.1.2-alpha.2`（0a53fb55be），234 commits。
> 插件仓库：`huanlinoto/dsh-plugin-better-glob`（npm `@huanlin/dsh-plugin-better-glob`）。
> 证据均为对 `D:/Projects/deepseek-harness/dsh` 的只读 git 查询（git show / diff / grep，未改动 dsh 树任何文件）。

## 结论 —— ⚠️ 需适配

**一处必改**：alpha2 把 `FIRST_PARTY_SECTION_ORDER` 从 `@deepseek-ai/dsh-system-prompt` 的导出中移除（私有化为内部 `SECTION_ORDERS` + 新公开方法 `systemPrompt.getSectionOrder(name)`）。本插件 `src/index.ts` import 了它，且**已发布的 `lib/index.js` 顶部有对应的 ESM 具名导入**——不改则 dsh web 启动加载插件时直接抛
`SyntaxError: ... does not provide an export named 'FIRST_PARTY_SECTION_ORDER'`，整包加载失败（fail loud）。
修复是约 3 行的机械改动（改用 `ctx.systemPrompt.getSectionOrder('TOOL_GLOB')`，数值仍为 1400）；除此之外，本插件用到的全部 dsh API 面在 alpha2 中逐项验证**无变化**，peer semver 范围也已满足 alpha.2。

**peerDependencies 匹配性评估**：`^0.1.2-alpha.1` 对 `0.1.2-alpha.2` **已满足** —— 按 semver 预发布规则，`^0.1.2-alpha.1` ≡ `>=0.1.2-alpha.1 <0.2.0`，`0.1.2-alpha.2` 与比较器共享 [0,1,2] 元组且 alpha.2 > alpha.1，故匹配；`@deepseek-ai/cordis ^4.0.1` 同理含 4.0.2。**严格说不改也能升**，但建议对齐为 `^0.1.2-alpha.2`（见迁移步骤，属卫生性修改）。⚠️ 语义注意：`^0.1.2-alpha.x` **不会**匹配未来的 `0.1.3-alpha.1`（元组 [0,1,3] 上没有带预发布的比较器）——下次 alpha 跟版仍需再抬范围。

## 迁移步骤

**顺序很重要：先把运行中的 dsh 宿主升到 alpha.2（pull + pnpm install + pnpm run build，见 AGENTS.md 的 DSH checkout SOP，由人类执行），再做插件侧适配** —— 新 API `getSectionOrder` 只存在于 alpha.2 的 `source/current`；若在宿主升级前重建插件，typecheck 反向失败。

1. **改 `src/index.ts`（唯一的代码改动）**：删除第 39 行
   ```ts
   import { FIRST_PARTY_SECTION_ORDER } from '@deepseek-ai/dsh-system-prompt'
   ```
   给 `shadowSection` 增加 order 入参（第 72 行起）：
   ```ts
   export function shadowSection(caps: BetterGlobCaps, order: number): PromptSection {
     // ...
     return {
       name: 'tool:glob',
       order,
       text: /* 原文不变 */,
     }
   }
   ```
   并在 `apply`（第 111 行起）经新 API 解析，与 alpha2 内置 glob 的写法逐字对齐（fs/tool-fs-search/src/glob.ts:302 @ alpha2）：
   ```ts
   const section = shadowSection(caps, ctx.systemPrompt.getSectionOrder('TOOL_GLOB'))
   ```
   > 不推荐的替代：把 order 硬编码为 `1400`。alpha2 数值恰好未变，能编译能跑，但上游再挪段位时会静默失配（遮蔽失效表现为提示词文案重复/错序，不报错）。走 `getSectionOrder` 与上游取值恒同源。
2. **无需改动的文件（明说）**：`src/tool.ts`、`src/argv.ts`、`src/caps.ts`、`tests/`（rg 确认 tests 无 `FIRST_PARTY_SECTION_ORDER` 引用）、`cordis.patch.yml`（insert 行结构未变）、`tsconfig.json`、`scripts/relink-deps.mjs`、`pnpm-workspace.yaml`、README（除可选的版本说明外）。
3. **package.json（可选但建议）**：4 个 `@deepseek-ai/dsh-*` peer 范围 `^0.1.2-alpha.1` → `^0.1.2-alpha.2`，`@deepseek-ai/cordis` `^4.0.1` → `^4.0.2`（均非必需，当前范围已满足 alpha.2）；插件自身版本 `0.1.0` → `0.1.1`（`shadowSection` 签名有变，属插件自身 API 变更）。
4. **重建 `lib/`**：
   ```powershell
   Push-Location D:/Projects/deepseek-harness/dsh-plugin-better-glob
   pnpm run typecheck    # junctions 指向升级后的 source/current，会立刻验证第 1 步
   pnpm test             # 40 用例（真实 ToolRuntime + SystemPrompt 组合 preflight，即对 alpha.2 的集成验证）
   pnpm run build        # prebuild 自动 relink junctions；tsdown 出 lib/index.js + tsc 出 lib/types/
   Pop-Location
   ```
   注意 `build` 脚本里的清理在 win32 若失败，手动 `Remove-Item lib -Recurse -Force` 后重跑（本仓库 build 为 `tsdown && tsc`，无 `rm -rf`，一般不触发）。
5. **profile 端生效**：`link:` 引用下，第 4 步重建 `lib/` 后 profile 的 `~/.dsh/profiles/web/node_modules/@huanlin/dsh-plugin-better-glob/lib/` 直接可见，**无需 `dsh plugin add` 重装**（也不要对 link 引用跑 `dsh plugin update`，无效操作）。
6. **对外发布**（按 huanlinoto 发布 SOP）：`git add` 源码改动 + 预构建 `lib/` → commit（`v0.1.1: adapt to dsh 0.1.2-alpha.2 getSectionOrder API`）→ `git push origin master`；`github:` 引用的部署执行 `dsh plugin --profile web update @huanlin/dsh-plugin-better-glob`。npm registry 渠道：重建 `lib/` 后 `npm pack --dry-run` 核对 files（lib/ + cordis.patch.yml）再 `pnpm publish`。
7. **最后**：重启 `dsh web` 进程 + 浏览器硬刷新（`Ctrl+Shift+R`）—— 由人类执行。

## 升级后验证清单

以下全部在 **dsh web 重启 + 浏览器 `Ctrl+Shift+R` 硬刷新之后**进行：

2. **阴影生效（agent 层）**：在会话中让模型执行一次 glob（如 `glob pattern: "**/*.ts"`）——正常返回且走的是本插件的 ripgrep argv；检查 `~/.dsh/profiles/web/node_modules/@huanlin/dsh-plugin-better-glob/lib/index.js` 存在且第 1 行 import 的符号在 alpha.2 中有效（应已不含 `FIRST_PARTY_SECTION_ORDER`）。

7. **grep 未被波及**：跑一次 `grep` 确认内置 grep 工具行为不变（本插件明确不触碰）。
8. 回归基线：`pnpm run typecheck`、`pnpm test`（40 用例）在宿主升级后的 source/current 上全绿。
