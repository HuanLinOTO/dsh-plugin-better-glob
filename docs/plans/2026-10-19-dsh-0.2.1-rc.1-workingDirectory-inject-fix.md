# dsh 0.2.1-rc.1 适配记录：missing `workingDirectory` inject（dsh-plugin-better-glob）

- 日期：2026-10-19
- 目标树：本机 `~/.dsh/source/current`（`0.2.1-rc.1`，junction 到 `D:/Projects/deepseek-harness/dsh`）
- 现象：`glob` 每次调用都失败，报 `cannot get property "workingDirectory" without inject`
- 影响：本插件 shadow 掉内置 `glob` 后，工具调用**全部**失败（`grep` 不受影响，内置注册未动）

## 根因

`runRipgrep`（`packages/fs/tool-fs-search/src/search-core.ts:236`）在执行期解析 agent 工作目录：

```ts
const workdir = exec.agent === undefined
  ? process.cwd()
  : await ctx.workingDirectory.ensure(exec.agent, exec.signal)
```

内置 `tool-fs-search` 的 inject 已含 `workingDirectory`（`src/index.ts:71`），本插件复用同一 `runRipgrep` 却仍声明 `['tools','systemPrompt','subprocess','agents']`——`ctx.workingDirectory` 的属性访问在 cordis fiber 树上找不到服务，抛 `without inject`。

引入提交：`79bd3d8da7 feat(session): centralize working directories and directory context`（2026-10-06，早于 `dsh-v0.2.1-alpha.2`）。alpha.5 迁移文档 `J1-14` 已记「`dsh-tools` 要求 `dsh-working-directory`」，触点分析表把 inject 写成四服务而漏了这一项执行期依赖 —— 教训：**复用他包导出的执行函数时，服务面必须覆盖该函数的运行期读取，而不只是本插件 `apply` 自己动的服务**。

## 行动

1. `src/index.ts`：`inject` → `['tools','systemPrompt','subprocess','workingDirectory','agents']`，JSDoc 说明来源。
2. `tests/inject.spec.ts`（新增）：断言本插件 `inject` ⊇ 内置 `@deepseek-ai/dsh-tool-fs-search` 的 `inject`，并单点断言含 `workingDirectory`。上游 `tool-fs-search` 再增运行期服务时，该测试立即失败 —— 这是覆盖率盲区（`tests/tool.spec.ts` 只测纯投影函数，从不执行 `execute`）的兜底。
3. `lib/` 重建（预构建入库策略），profile `link:` 引用无需重装，重启 `dsh web` 生效。

## 验证

- `pnpm test`：6 文件 / 45 tests 全绿
- `pnpm run typecheck`：无错
- `pnpm run build` → `lib/index.js:411` 含 `"workingDirectory",`；`pnpm typecheck:tests` 覆盖 tests 类型面
