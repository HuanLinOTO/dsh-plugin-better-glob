## 行动

1. **J1-01（schemastery 惯犯）**：`dependencies` 的 `@deepseek-ai/schemastery` `^3.18.4` → `~3.18.5-alpha.2`（镜像官方 vendored pin；`^3.18.4` 不接纳 prerelease `3.18.5-alpha.2`）。官方包自身也是普通 `dependencies` 声明（`dsh-tools`/`tool-fs-search` 均 `workspace:~`），维持写法只升 range。
2. **J1-18 note 1（junction 假绿修复）**：`scripts/relink-deps.mjs` LINKS 增 `'@deepseek-ai/schemastery': $DSH_HOME/source/current/vendor/schemastery`——探测发现本地解析的是 pnpm store 的 **3.18.4** 旧副本（类型+运行时双面陈旧）。
3. **J1-18 note 5（stale exclude 回归通道）**：`pnpm-workspace.yaml` `minimumReleaseAgeExclude` 的 `schemastery@3.18.4`/`cosmokit@1.8.5` → `3.18.5-alpha.2`/`1.8.6-alpha.2`（跟随新 range 的安装期同名排除）。
4. **J1-19（tests 类型门）**：新增 `tsconfig.tests.json`（override `rootDir: "."`，`noEmit`）+ `typecheck:tests` 脚本——主 tsconfig `include: ["src"]` 从未覆盖 tests。首跑暴露 `tests/shadow.spec.ts:121` 存量类型债（`BetterGlobCaps.excludeDirs: readonly string[]` 不可赋 `BetterGlobConfig.excludeDirs: string[]`；两类型均插件本地、非本跳引入）。修复：`apply(ctx, resolveConfig({}))` → `apply(ctx, {})`——Loader 真实传参形状就是 schemastery 默认化 config，caps 形状在生产中不出现。
5. 版本号 `0.2.1` → `0.2.2`（沿仓库「适配即发版」惯例）。

## J1-14 传递影响（无代码改动，记录在案）

alpha.5 的 `runRipgrep` 内部经 `ctx.workingDirectory.ensure(exec.agent, exec.signal)` 解析工作目录（`search-core.ts:236`），`tool-fs-search` 的 peers 也新增了 `@deepseek-ai/dsh-working-directory`。本插件 execute 路径完全经 `runRipgrep`，故**装配本插件的组合必须同时挂 `dsh-working-directory`**——官方 shipped bundles（web-app/sdk-minimal/base）已默认携带，无(bundle)层行动；`exec.agent === undefined` 时回退 `process.cwd()`，单元测试不受影响。
