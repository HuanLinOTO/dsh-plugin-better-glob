## 行动

1. **RC1-07**：`src/index.ts` 监听从 `agent/session-start` 改为 `agent/created`；listener 改 `async`，语义保持非重入（`shadowed` WeakMap 守卫，重复事件 no-op），不做任何 await（rc.1 串行派发，listener 抛错会 reject 创建）。
2. **RC1-01**：4 个 `@deepseek-ai/dsh-*` peer `^0.1.5-rc.1` → `^0.1.7-rc.1`。
3. **RC1-15 核验**：`dsh.bundle.patch = "./cordis.patch.yml"` 仍合法；无被删字段。
4. **schemastery 依赖切换**（见「额外发现」）：`dependencies` 的 `schemastery@^3.18.0` → `@deepseek-ai/schemastery@^3.18.4`；`src/caps.ts:8` import 同步。
5. `tests/shadow.spec.ts` 事件名与用例名同步为 `agent/created`；`README.md` 两处机制描述同步。

## 额外发现（无对应卡，primary source 支撑）

rc.1 vendor schemastery 升 `@deepseek-ai/schemastery@3.18.4`（新增 `SchemaMode`/`Volatile`、`Schema` 变 3 泛型）。它与插件普通 `schemastery@3.18.0` 的 `declare global { namespace Schemastery }` 在 tsc program 内合并，使 `export const Config: z<BetterGlobConfig> = z.object({...})` 报 TS2322（`Schema<…,"plain">` 不可赋 `Schema<BetterGlobConfig>`；数组默认值 `excludeDirs` 触发）。按 `plugin-development-guide.md` 红线清单（vendor/schemastery 由宿主提供）改用 `@deepseek-ai/schemastery`，冲突消失。
